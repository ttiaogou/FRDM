# AI 回复草稿链路修复说明

本版本以 `Freedom-full-source.zip` 为基线，按用户确认的三项规则调整。

## 已修改行为

- 私信列表打开会话不再以前置平台 ID 采集作为硬条件。列表行、点击前新快照、点击后窗口和聊天标题仍必须一致；同名歧义、窗口变化或目标不一致时停止。没有平台 ID 时只使用本次访问的临时会话上下文，不用昵称合并长期历史。
- 普通 OCR 文字保持 `UNVERIFIED`，不会进入草稿模型上下文。只有独立验证为 `VERIFIED` 的文字才可生成草稿。
- 消息批次不再因旧消息失败而整体拒绝。适配器提供“最新可见行完整”证据后，较早行的截断、未识别或 OCR 部分失败可以被排除，继续使用最新完整消息。最新行不完整、方向不明、非文字、未验证或无法确认顺序时，最多自动重新读取两次；仍不确定则停止。
- 启动消息任务时检查模型配置和云处理授权，失败立即暂停并写明原因。每条消息生成时仍重新检查配置和授权，防止运行期间授权被撤回。
- 当前窗口消息始终是草稿锚点。有可靠的当前登录账号证据、联系人 ID、会话 ID 且历史包含当前可见消息锚点时，才拼接同一账号、同一联系人、同一会话的已验证历史。现有仓库没有账号归属证据时，不读取旧历史。

## 未改变的边界

没有删除原项目文件，没有修改 AccountBrowse 算法、手势参数、权限、持久化 key 或自动发送行为。普通 OCR 的可信度判定没有被放宽；模型生成后的草稿仍留在输入框中供人工审核和手动发送。

## 验证

已运行架构边界检查和 12 项架构检查器单元测试，均通过。新增 Kotlin 测试覆盖：未验证 OCR 拒绝、旧消息部分失败但最新完整时继续、最新不支持消息不回退、临时上下文、历史锚点合并和无账号证据时拒绝历史。

当前环境没有 Java、Gradle 或 Android SDK，因此 Kotlin/JUnit 编译、APK 构建和真机联调未验证，不将其描述为已通过。
