## 2. Entry, authority and lifetime boundaries

Service callback forwards through accessibilityEventForwarder; AndroidAccessibilityEventPipeline normalizes and emits UnifiedAccessibilityEntry events; AppCompositionRoot routes them to RunSessionCoordinator, then AiReplyModeRuntimeAdapter.onTargetApplicationEvent -> Runtime.schedule (4804). Page/session lifecycle remains in RunSessionCoordinator; task leases remain in TaskCoordinator (activeLease, run generation, revision); UiWriteAuthorization checks bound lease and current route at actual platform writes. AiReplyTaskOwnership delegates to TaskExecutionController. Runtime claimTaskOwnership (4007) coordinates page admission and rolls back denied claims; it is not a second lease owner.

| Lifecycle boundary | Existing behavior and dependency |
| --- | --- |
| New run | AiReplyModeRuntimeAdapter.onRunStarted resets only on non-retry, calls preparePageSelectedStartup then requests route observation. Runtime.scheduleInitialObservation (4534) checks configuration and archive admission, reloads only appropriate checkpoint when page-selected startup applies. |
| Event and window change | schedule (4804–4924) invalidates old OCR/visit and recovery samples before debounce, retains protected send/gesture observation and delegates channels; onGlobalTouchEvent (1636) participates in user-interaction gates. |
| Page pause | Adapter.saveProgressBeforeExit -> persistTaskProgressBeforeExit (3475) saves owned checkpoint only; if recovery pending preserves original; onRunPaused resets with preservePendingRecovery=false. |
| Service interrupt/disconnect | Adapter persists checkpoint, sets awaitingServiceReconnect and calls reset (3519); reconnect reestablishes observation/readiness then reloads both existing checkpoint paths with fresh verification. |
| Service destruction | Adapter saves progress then resets; distinguish from explicit user stop. |
| User stop | Adapter resets in try/finally and clears durable observation schedules only here (3514); ledger counts and unresolved follow-up remain durable. |
| Reset / route retirement | reset (3519–3633) cancels child, draft, gesture, observation and retry work, increments action generation, releases lease through original owner, clears transient state, optionally preserves pending recovery. invalidatePendingMessageRead (9407) also invalidates read coordinator, visit token and model retries; this crosses several task lifetimes. |

Do not conflate process/Service state, run generation, observation generation, lease revision, sessionActionGeneration, fullInspectionCallbackToken, draftVisitToken, OCR coordinator request generation and individual retry generations. Each protects a different boundary.

## 4. High-risk couplings and cleanup candidates (not authorized fixes)

1. `handleInspectionSnapshot` (1744–3052) combines route observation, recovery, startup, task handoff and business dispatch. It should remain the orchestrator; migrate cohesive child responsibilities first, not wholesale copy a 1,300-line method.
2. `handleMessageReadBatch` (5599–6303) mixes greeting/private/draft/send-confirmation paths; separate only after proving the original admission and side-effect ordering. `invalidatePendingMessageRead` clears both task-specific bindings and shared visit token; not an independent OCR-only reset.
3. `regionRefreshTask` (337) has 11 textual references in Runtime, but no non-null assignment found; shared regionRefreshChannel is live. Candidate redundant legacy timer handle; verify full references, reflection/tests and reset behavior before any separately authorized removal.
4. `latestGreetingMessageBatch` (790) has only four textual references and no explicit null assignment; `latestPrivateMessageBatch` (792) is explicitly cleared in detail-to-list recovery (4213), not in invalidatePendingMessageRead. Pre-send readers (1714–1741) check task state and window session key. This is a lifetime audit risk, not proof of stale-send failure: test same-window new visit, reset, lease switch and stale callback before deciding whether a change is needed.
5. `sessionManagerState` setter is not a simple compatibility alias: it updates executor state and RecoveryContext pause evidence. Other currentSession accessors delegate. Do not delete these wrappers merely to reduce lines or split their writes.
6. `reset` cancels multiple owners, resets transient states and conditionally preserves recovery; broad migration can accidentally clear durable ledger/checkpoint or retain old callback authority. Preserve ordering and reentrancy; do not infer all fields are reset solely from declaration.
7. RecoveryContext and dispatcher/reducer are complementary evidence and transition mechanisms, not demonstrated duplicate state machines. The dispatcher uses a shared manager when provided; isolated fixtures have fallback. Preserve production path and tests.
8. Existing diagnostic comment/3500-char threshold discrepancy remains as recorded in R06-G. No file identified as safely deletable based on this scoped audit.
