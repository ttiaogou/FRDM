## 13. 状态机与防重复机制（Stateful Memory & Cooldown）

### 13.1 重复回复约束

禁止对同一目标对象或同一聊天上下文中的同一回复任务，在短时间内重复触发相同的回复逻辑。

防重复判断必须区分“同一条消息的重复处理”和“同一用户后来发送的新消息”。不得仅因为用户 ID 相同，就把该用户后续所有新消息都当成重复消息。


### 13.2 本地短期记忆缓存（Memory Buffer）

必须建立本地短期记忆缓存，记录最近已处理或已回复的对象和内容。原文要求记录的用户 ID 与话术哈希必须保留，不得被其他字段替代。

在此基础上，建议同时记录：
- 目标应用标识；
- 当前账号标识；
- 会话或聊天上下文标识；
- 用户 ID；
- 接收消息 ID（目标应用能够提供时）；
- 回复话术哈希；
- 回复任务唯一标识；
- 任务创建时间、处理时间和冷却到期时间；
- 当前任务状态及发送结果。

去重判断应结合用户 ID、会话上下文、消息标识和话术哈希等信息，避免因单一字段相同而误判不同消息。

### 13.3 冷却时间（Cooldown）与任务状态

必须设置明确的冷却时间，避免在设定周期内对同一特征对象或同一回复任务产生机械化的重复响应。冷却时间应有清晰的作用范围、起算时点和到期条件。

对回复任务至少区分以下状态：待处理、正在执行、已完成、执行失败、发送结果未知。收到重复事件时，必须先检查 Memory Buffer 和任务状态；已完成或正在执行的同一任务不得再次启动。

对于发送结果未知的任务，必须先确认实际发送状态，再决定是否重试。不得在没有确认的情况下盲目重复发送。

## 15. AI Reply 业务边界与发送安全

1. AI Reply 必须独立于 AccountBrowse。
2. AI Feature 不得直接调用 Android Service 或其他 Feature 的内部类。
3. Momo 适配器负责页面结构、消息解析、输入位置和动作映射；不得决定 AI 回复内容。
4. AiProvider 只负责结构化模型请求与返回结果；不得读取页面或决定是否发送。
5. 会话和消息由 Conversation Repository 管理；回复任务由 ReplyTask Repository/Queue 管理。
6. 群聊、图片、语音、视频、系统通知以及无法确认消息方向的消息，不得自动回复。
7. 消息方向、发送者或会话身份存在不确定性时，停止自动回复。
8. 会话切换、页面变化、消息批次过期或发送目标不一致时，必须重新校验。
9. 发送结果未知时，进入待核验状态，不得猜测发送成功或盲目重试。
10. AI 回复任务应具有明确的状态转换和幂等 ID，不得因事件重复到达而重复调用模型或重复发送。
