## 7. 节点检索与事件响应边界（Node & Event Boundaries）

### 7.1 全局节点遍历频次约束

- 禁止在 `onAccessibilityEvent` 回调中无条件、高频次调用 `getRootInActiveWindow()` 并递归遍历整棵节点树。
- 必须通过 `AccessibilityServiceInfo` 在 XML 或代码中严格限定目标包名（`packageNames`）与监听的事件类型（`eventTypes`），不得无差别全景监听手机全局状态。
- 对重复、密集事件进行合并、去重、节流或延迟处理；具体策略需按事件类型和业务需要区分。
- 事件回调内优先做轻量过滤、映射和转发；耗时工作交由受控调度器处理。

### 7.2 节点检索行为约束

- 禁止单一依赖可能随固件或应用版本变化的静态 View ID 锚定核心流程。
- 必须结合文本（`text`）、`contentDescription`、类名（`className`）、父子关系、边界和页面上下文等可用证据进行多维联合校验。
- 循环查找或等待节点出现时，必须设置最大超时阈值和最大重试次数；原文示例为最多重试 5 次，每次间隔采用随机步长。实际参数应尊重当前功能已经验证的配置，不得借本规范擅自修改既有重试次数。
- 节点快照必须有边界：限制遍历深度/节点数/执行时间，记录命中依据和失败原因。
- 不得把 Android 节点对象长期保存到 Domain、Repository、任务队列或 RuntimeSnapshot 中。
- 节点失效、窗口变化或检索超时后，必须重新获取并验证，不得继续使用旧节点引用。

### 7.3 事件映射

事件进入业务前，应尽可能归一化为与 Android API 类型解耦的内部事件；保留必要来源信息、时间戳、目标包名、窗口/页面上下文和事件代次。不同事件类型采用不同策略，不得把页面内容变化、窗口切换、触摸交互和服务生命周期事件混为一类。

## 8. 交互执行与手势通道边界（Interaction & Gesture Boundaries）

### 8.1 屏幕手势唯一通道

- 所有屏幕单击、双击、长按、滑动、滚动、拖动等屏幕交互动作，必须且只能通过 `AccessibilityService.dispatchGesture()` 的物理屏幕坐标手势实现。
- 不得使用 `AccessibilityNodeInfo.ACTION_CLICK`、`ACTION_LONG_CLICK`、`ACTION_SCROLL_FORWARD`、`ACTION_SCROLL_BACKWARD` 或其他节点 Action 替代上述屏幕手势。

这是 Freedom 的项目执行约定，不应误写成 Android 平台禁止所有 Node Action 的通用结论。
 `ACTION_SET_TEXT` 属于文本输入机制，不是屏幕点击/滑动手势的替代方式；其使用仍须遵守第 12 节的输入约束。

### 8.2 手势串行与并发
- 不得在没有并发控制的情况下向 `dispatchGesture()`，连续派发多条相互冲突的手势
- 手势按业务时序串行；确需协同的动作必须有明确的并发设计和状态所有者。
- 手势队列应能取消、清空或隔离失效命令。
- 每个 GestureCommand 必须有唯一 ID、运行代次和目标上下文。

### 8.3 回调闭环

所有通过 `dispatchGesture()` 发起的手势，必须实现 `GestureResultCallback`，处理 `onCompleted` 与 `onCancelled`。

- 回调必须闭合对应手势状态机。
- 完成、取消、超时和异常必须产生可追踪结果。
- 旧任务回调不得更新新任务状态。
- `onCancelled` 不代表可以不经检查立即原样重试。
- 发送结果未知或当前窗口已变化时，应停止并重新校验，不得盲目重试。

## 9. 空间几何与触控坐标边界（Spatial & Coordinate Boundaries）

### 9.1 点击坐标、安全内收与空间扰动

1. 禁止固定中心点机械点击
严禁每次都直接获取控件边界矩形（Rect）的绝对中心点（X_center, Y_center），并将其作为固定的最终点击落点重复执行。
控件几何中心可以作为计算坐标的参考基准，但不得把同一个中心像素点无条件作为所有点击操作的最终坐标


2. 规定有效区域内的随机落点：
任何点击动作都必须先确定目标控件当前的有效触控区域，再在该区域内引入高斯分布或均匀分布的随机偏移量。不得在未计算有效区域的情况下直接对屏幕坐标任意加减像素

计算时必须设置安全内边距。例如，可以按照控件边界宽度和高度分别向内收缩约 15%，形成可用采样区域，15% 是常用参考参数，不代表所有尺寸和形状的控件都必须使用同一比例；实际内收量必须保证采样区域仍然有效

3. 随机采样必须受有效区域约束：
- 高斯分布采样应采用截断分布或越界后重新采样；
- 均匀分布采样的上下界必须直接取自安全内收后的有效区域；
- 不得让最终坐标落在控件有效区域之外、屏幕之外或系统手势冲突区域；
- 不得通过简单裁剪使大量采样结果堆积在边界上，造成新的坐标偏差。

如果控件过小、不规则或内收后没有有效采样区域，应重新计算该控件的实际有效触控区域；仍无法得到可靠落点时，停止该次点击并报告原因，不得退回到未经校验的固定中心点点击。

### 9.2 滑动轨迹非线性约束
1. 禁止使用两点直线插值生成滑动轨迹：
- 严禁使用两点之间的直线插值（Linear Interpolation）作为滑动或拖动操作的空间轨迹。

2. 规定贝塞尔曲线轨迹：
- 所有滑动与拖动操作必须通过二次或三次贝塞尔曲线生成轨迹，并根据动作起点、终点、方向和操作区域设置动态控制点。不得用简单的两点直线插值代替规定的曲线路径。

3. 补充时间参数化与速度曲线：
贝塞尔曲线定义的是空间路径形状，本身并不自动产生加速、匀速和减速效果。为实现原文要求的平滑运动过程，必须同时为轨迹配置时间参数化或速度曲线，明确：
- 起始阶段的加速过程；
- 中间阶段的速度变化或相对平稳区间；
- 结束阶段的减速过程；
- 总持续时间及采样点的时间分布。

路径几何与时间变化必须共同生成最终 GestureDescription，不能只生成贝塞尔路径而忽略执行时间，也不能只调整持续时间而仍使用固定直线匀速轨迹。
