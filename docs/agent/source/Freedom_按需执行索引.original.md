AGENTS.md — Freedom 工程架构与执行规范

0. 最高执行原则
架构基准不可反向删减：以 Freedom 的总体架构、目标逻辑目录、组件职责、状态所有权与行为边界为准；未实现组件标为“未实现/待建设”，严禁因当前代码未实现或为形式整齐/大规模改名搬迁/重写而删减目录或组件；现状与基准不一致须记录目标组件、当前承担者、实现/混杂状态及对齐方案与影响；渐进演进，先保行为不回退。

技术修正不取消原目标：与 Android 能力/API/现状冲突时，须标记“冲突/需决策”或“技术表达需修正”，说明冲突位置、平台限制、影响范围与可选实现，优先保留原目标；不得以“技术上不方便/当前没有实现/更简单”删减原目标；未经明确授权，不得改动既有业务行为、默认配置、UI 交互、持久化契约或已验证算法。

项目范围限制：坐标扰动、轨迹参数化、等待时间分布与输入节奏仅用于内部交互执行、操作稳定性、节律控制及输入检查，严禁擅自解释或扩展为设备身份伪装、平台风控绕过、反作弊或第三方检测对抗。
