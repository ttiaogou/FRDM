# Freedom — Android 无障碍落地开发手册

## 0 项目架构强制约束（所有代码任务必读）

1. **架构冻结**：以现有架构及已批准基准为准，未经用户明确授权，禁止新增、重建、替换或重构架构，禁止改变模块边界、依赖方向、组件职责及状态所有权。
2. **原架构内修复**：功能开发、缺陷修复及优化必须在现有架构内完成，优先维护原有组件和调用链，禁止通过新增架构层解决现有问题。
3. **职责唯一**：禁止新增职责重复、重叠的协调器、管理器、状态机、调度器、识别器、恢复机制及兼容层；禁止绕过既有统一入口。
4. **状态唯一**：同一权威状态只能存在一个所有者，禁止平行维护、跨层修改及重复决策。
5. **操作权唯一**：谁的页面，谁的任务，谁的操作权。页面变化后暂停旧任务，安全释放操作权，新任务按照原有流程运行。页面未确认时仅允许只读观察，写入须经过现有租约及授权门禁。
6. **恢复隔离**：正常任务切换与异常恢复必须分离，禁止旧任务的业务恢复阻塞新任务正常运行，但不得绕过必要的安全隔离及原有检查点验证。
7. **业务保护**：未经授权，禁止改变任务内部流程、页面指纹、手势算法、坐标、空间、时间节律、输入规则、默认配置、UI 交互及持久化契约。
8. **施工门禁**：修改前核验仓库、授权分支、提交 SHA 及工作区（如适用），审计现有架构、职责归属和调用链；修改后执行原有架构硬检测及回归验证，如实报告未验证项。禁止绕过、削弱或删除检测规则、安全断言和有效测试。
9. **冲突处理**：发现现有架构无法满足任务要求时，必须报告冲突及原因，未经用户授权不得自行扩展架构。

## 1 服务配置、权限状态与生命周期落地

  ### 1.1 配置收敛（`accessibility_service_config.xml` 或动态配置）
  - 严格限定目标 `packageNames` 与所需 `eventTypes`，避免全局无差别监听；按需声明 `canRetrieveWindowContent`、`canPerformGestures`、合适 `notificationTimeout` 与 `accessibilityFlags`，防止无关事件淹没主线程或引发高频节点树遍历。
  - 若配置项调整影响既有行为、权限或监听范围，须先核对架构规范变更纪律，必要时走独立确认。
  
  ### 1.2 多维状态独立与诊断
  - 将应用进程状态、无障碍授权状态、悬浮窗授权状态（独立于无障碍）、服务绑定状态、服务初始化状态、用户运行授权（`RunStateRepository`）、页面运行时生命周期（`RunSessionCoordinator`）、业务任务状态及手势执行状态分开建模与查询，不得用一个布尔值替代。
  - `onServiceConnected` 仅代表服务连接回调到达，不等同于业务就绪；`onInterrupt` 仅代表系统中断，不等同于服务销毁或无障碍授权丢失；回调缺失不可推断事件未发生，进程被强杀或崩溃时应结合上次运行快照、启动记录与会话标识在下轮启动时识别“上次未正常收尾”。

  ### 1.3 系统限制与状态可观测边界（非人工接管）
  - 不承诺在任何系统状态下强制自行重启服务；若系统级服务断开或授权被撤销，界面仅展示实际状态并提示系统设置项，**严禁将此演化为“等待人工接管/人工点确认继续”的业务流程阻塞**；一旦系统服务重连或条件恢复，系统须自动触发重检并恢复运行。
  - 日志须带时间、进程/运行会话标识、服务状态、RunMode、RunStatus、任务 ID、页面指纹摘要、退避阶段、事件类型与错误原因等结构化字段；敏感消息正文严禁无边界写入普通日志。

## 2 统一入口、页面指纹门禁与强自动恢复（含退避节奏）

  ### 无障碍统一入口与页面指纹门禁
  - 无障碍事件经既有轻量过滤、归一化及统一入口进入现有观察与任务协调链路；Adapter 提供当前窗口/包名/页面证据，`PageObservationCoordinator` 复用既有页面指纹匹配体系（Page Fingerprint），`RunSessionCoordinator` 据此协调页面所属任务，不自行另建页面识别或操作权体系。

  ### 页面指纹决定任务启动与推进
  - 仅当当前页面指纹与目标任务预期指纹匹配（且恢复场景满足连续稳定采样门限）时，才允许获取/转交任务租约并启动或恢复执行；只读观察、任务准备及最终 UI 写入许可必须区分，具体按第 0 节第 4～6 条执行；
  - 当页面指纹不匹配、处于过渡/加载态或收到未知事件时，任务进入**受控重检退避状态**，严禁引入人工接管静默期，也不因单次未匹配或未知事件将任务彻底终止。

  ### 指纹重检与自动恢复退避节奏（明确工程参数）
  - **阶梯退避序列**：在页面指纹未匹配、检查点待对齐或自动恢复等待期间，重检调度按 **`500ms → 1s → 2s → 5s → 10s`** 逐步推进。
  - **长期等待封顶**：当连续未对齐进入长期等待态时，单次重检间隔**最多每 `30s` 一次**（不得无限延长或进入死锁挂起）；可在基准间隔上叠加受控有界抖动，但必须严格受该阶梯与 `30s` 上限约束。
  - **即时唤醒与复位**：退避等待期间，一旦新的无障碍事件触发页面指纹重新匹配成功（且运行代次与租约校验通过），须立即取消当前退避定时器、复位退避阶段并无缝推进恢复或任务执行，无需死等当前周期结束。
- **强自动恢复闭环（10 步重连恢复 + 代次隔离）**：
  1. 查询并分别记录无障碍授权与悬浮窗授权；
  2. 确认服务已连接；
  3. 完成服务初始化并建立新的 Gateway / 事件路由能力；
  4. 读取并校验原有运行授权与所属业务检查点等可安全恢复元数据（严禁保存或恢复失效的 `AccessibilityNodeInfo`、Window 或 Service 对象）；
  5. 确认非用户主动停止；
  6. 确认运行授权及目标任务仍然有效；当前页面属于其他任务时按第 0 节第 5、6 条完成交接，不因旧任务模式阻塞新任务；
  7. 重新识别当前包名、页面指纹、窗口和会话，不沿用断开前节点对象（指纹变更时仅重置稳定采样计数，不销毁恢复上下文）；
  8. 确认业务检查点成立且无未决危险操作；
  9. 由 `RunSessionCoordinator` 协调页面所属任务，`TaskCoordinator` 管理任务租约，所属业务状态所有者按原有恢复机制执行恢复决策；
  10. 将恢复结果、指纹匹配状态或当前退避阶段写入日志。
  - 若当前页面指纹尚未匹配、检查点待对齐或存在未决操作，保持受控退避重检并记录原因，严禁盲目猜测页面、重放未知手势或盲目重发消息。
- **代次隔离与幂等**：
  - 每次运行分配唯一 run/session generation 标识；重连或恢复须幂等，避免重复启动相同任务实例；清理或隔离旧手势队列、退避定时器、事件订阅与回调引用，旧代次异步回调严禁修改新代次状态。

## 3 节点、手势、坐标、节律、与可视化约束

### 3.1 节点与事件
 - 须在 AccessibilityServiceInfo 严格限定 packageNames 与 eventTypes，禁全局无差别监听；
 - 禁在 onAccessibilityEvent 中无条件高频 getRootInActiveWindow() 递归整棵节点树，须合并/去重/节流/延迟并将耗时工作交受控调度器。禁单靠静态 View ID 锚定核心流程，须结合 text、contentDescription、className、父子关系、边界、页面上下文多维联合校验；
 - 循环找节点须设最大超时与最大重试次数（参考最多重试 5 次、随机步长，尊重既有配置，不擅改），快照须限深度/节点数/耗时并记录命中/失败原因，节点失效/窗口变化/超时须重取重验。事件须归一化并按类型分策处理。
 - **局部重试与外层持续恢复分层**：节点检索的最大次数与超时仅约束当前一次检索事务；达到上限须结束本轮查询，报告可重新尝试（`RETRYABLE`）或相应原因，并交由页面观察/恢复调度重新获取新快照和校验状态。只要用户未主动停止且任务仍有效，外层恢复事务不因局部查询耗尽而永久失败，须按第 2 节有界退避持续重检；不得在单个检索循环中无限自旋、沿用旧节点或跳过页面指纹及 UI 操作权校验。

### 3.2 手势唯一通道与闭环
 - 所有单击、双击、长按、滑动、滚动、拖动必须且只能通过 AccessibilityService.dispatchGesture() 物理坐标手势实现，禁以 ACTION_CLICK/ACTION_LONG_CLICK/ACTION_SCROLL_FORWARD/ACTION_SCROLL_BACKWARD 等节点 Action 替代（ACTION_SET_TEXT 属文本输入，须受输入约束）。
 - 手势按业务时序串行、可取消/清空/隔离，每条 GestureCommand 须带唯一 ID、运行代次与目标上下文；
 - 须实现 GestureResultCallback 闭合 onCompleted/onCancelled/超时/异常状态，旧回调禁改新状态，onCancelled 或结果未知/窗口变化须停止并重检，禁盲目原样重试。

### 3.3 点击坐标
 - 禁固定中心点机械点击；须先确定目标控件安全内收后的有效触控区域（如宽高各内收约 15% 作参考，须保证有效区域存在），再在有效区内用高斯分布（截断或越界重采样）或均匀分布做随机偏移，禁落点越界、出屏、入系统手势冲突区或简单裁剪致边界堆积；过小/不规则/无有效区时重算或停止并报告，禁退回未经校验的固定中心点。

### 3.4 滑动轨迹与起止点
 - 禁两点直线插值或固定直线匀速轨迹；
 - 须通过二次或三次贝塞尔曲线按动作起点、终点、方向与操作区域设置动态控制点，并配置时间参数化/速度曲线（起速加速、中段速度变化或相对平稳、收尾减速、总时长及采样时间分布），由路径几何与时间变化共同生成最终 GestureDescription。
 - 禁起终点机械固定：起点基于有效滑动区基准加受边界约束的正态偏移（参考 ±15～25px，按分辨率/区域/类型配置），距离与终点结合实际视口/滚动容器/目标控件边界加动态步长浮动（参考 ±5%～10%），均须边界校验（越界重采样或重算可用区间，禁直接越界或静默取消扰动，禁牺牲操作有效性）。

### 3.5 时间节律
 - 禁连续操作依赖固定硬编码延时（如全程固定 Thread.sleep(1000)）或瞬时高频连击；
 - 交互前后停顿/等待/决策间隔须用匹配量纲的有界概率分布（如指数/截断正态/Gamma/对数正态等，设最小/最大与超时，禁负数或无上限等待，固定值仅用于明确超时/系统接口/已验证时限）；
 - 长周期任务须拆阶段并设带状态检查与超时的宏观阶段停顿。


### 3.6 手势可视化
 - 每次自动屏幕手势须实时可视化（点击显位置；滑动/拖动显起点、实时轨迹、终点、方向），预览与执行必须共用同一 GestureCommand 与同一份坐标/路径/时长数据源，禁双套独立计算；屏幕旋转/分辨率/窗口变化或手势取消时须重检/重生成，禁执行过期坐标。
 - **权限与能力验证**：手势可视化所依赖的悬浮窗/无障碍覆盖层能力应在执行前按 Android 版本、授权状态和窗口上下文核验；权限缺失或显示层不可用时必须记录具体原因并进入受控等待/恢复或阻断该次自动手势，严禁以关闭可视化来绕过这一既有强制要求，也不得擅自要求人工确认才能恢复。
 - **性能与异常闭环**：展示层应复用同一条 `GestureCommand` 的数据，避免额外高频节点扫描与重复路径计算；控制绘制频率、内存和生命周期资源，避免遮挡实际操作区域。显示创建/刷新失败、手势取消、服务断连或旋转/分辨率变化时，应清理失效轨迹、记录失败类别并重新校验页面/坐标及运行代次，不得凭过期预览执行或直接推断业务动作成功。

## 4. 输入节奏、AI 回复防重与工程验证

### 输入通道与节奏

  - 严禁通过 `ACTION_SET_TEXT` 或剪贴板一次性整段填充后立即发送。
  - 文本须拆成 **2～3 个用户感知字符**分段（优先标点或词语边界切分，严禁拆开表情或组合字符；单字符无法继续拆分时作为例外直接写入一次，但仍须执行停留与检查），逐段更新输入框，每段停留 **500～900ms**（有界均匀分布起点），检查未完成时不得因为时间到了就进入下一段。
  - 停留期须实际检查错别字、内容完整性、文本是否截断或异常及输入框是否仍处预期会话/页面指纹，严禁把等待时间结束当作自动发送条件；检查通过方可发送，发现内容不正确或状态变化应停止当前发送动作并触发上下文与页面指纹重检。
  - 发送按钮点击同样基于当前有效触控区域及安全内边距做高斯或均匀分布随机坐标扰动，禁固定中心/同像素点点击或致偏离/误触邻近控件。

### AI 回复安全与去重（停手重检 ≠ 人工挂起）
  - `AI Reply` 独立于 `AccountBrowse`，禁直调 Android Service 或其他 Feature 内部类；`MomoSocialAdapter` 不决定 AI 回复内容，`AiModelProvider` 仅处理结构化请求与返回结果、不读界面/不决定发送/不持会话状态或回复队列；会话/消息归 Conversation Repository，回复任务归 ReplyTask Repository/Queue。
  - 群聊、系统通知及无法确认消息方向的消息严禁自动回复；方向、发送者不确定时仅跳过/停止该条消息的自动回复并保持观察，不得锁死全局任务或等待人工仲裁；页面指纹/页面变化、消息批次过期或发送目标不一致须重新采集并校验页面指纹；发送结果未知转自动核验状态（重新读取会话记录核对是否已发出），禁猜测成功、禁盲目重试、禁挂起等人工介入；任务须具明确状态转换与幂等 ID。
  - 本地短期记忆缓存须保留**用户 ID**与**话术哈希**，并结合应用/账号/会话/消息 ID/任务 ID/时间/冷却到期/状态及发送结果联合判重，区分“同消息重复处理”与“同用户新消息”；设明确冷却时间及`待处理`/`正在执行`/`已完成`/`执行失败`/`发送结果未知`状态。

- **可测试性与改后验收**：
  - 时间、随机数、调度器和平台 Gateway 尽量接口注入；Domain 与 Application 须可在无真实 Android Service 下单元测试，严禁为测试转移生产状态所有权。
