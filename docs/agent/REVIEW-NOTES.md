# 落地手册修订记录与未决意见

> 本文记录原三处规范调整及其它未决意见；PP 第 0 节架构强制约束和相关职责修订也已获用户批准；规则执行以 parts/ 与 source/Android_无障碍落地开发手册.current.md 为准。原件在 source/*.original.md 保留，不将未批准的其它审阅建议视为强制规则。

## 1. 媒体消息不再一概禁止自动回复（已批准）

- **原文位置**：§4「AI 回复安全与去重」。
- **已批准修改**：仅删除“图片、语音、视频”被一概禁止自动回复的文字；继续保留群聊、系统通知、消息方向不明等其它限制，以及对会话、页面指纹、发送状态和重复发送的安全检查。
- **边界**：本轮只修订规范，不实现或开启媒体识别、发送等运行时功能。

## 2. 节点查询局部上限与持续自动恢复（已补充）

- **原文位置**：§3.1 节点检索；外层依据 §2 UNKNOWN/页面指纹重检。
- **已批准补充**：局部检索保留有限次数和超时；达到上限转可重新尝试（RETRYABLE），由外层恢复事务按既有受控退避继续观察。未主动停止且任务仍有效时，不以单轮节点检索失败永久终止任务。
- **保护**：不修改原来的次数参考、退避序列、30s 上限、指纹门禁或 UI 操作权。

## 3. 实时手势可视化的权限、性能与异常（已补充）

- **原文位置**：§3.6 手势可视化。
- **已批准补充**：执行前核验显示能力；显示失效须记录原因并进入受控恢复或阻断本次自动手势；限制绘制开销并处理取消、断连、旋转及过期坐标。
- **保护**：不取消每次自动屏幕手势必须可视化，也不改动现有手势算法或轨迹数据源。

## 4. 一律通过 dispatchGesture 与无障碍能力差异（技术核验）

- **原文位置**：§3.2 规定屏幕交互手势统一走 dispatchGesture()。
- **关注点**：系统版本、手势冲突、操作系统取消回调、无障碍权限变化可能限制执行，但不能把回调完成等同于业务动作完成。
- **建议**：保留统一手势通道目标；将平台限制和失败分类交由专用适配器、测试与页面核验处理。

## 5. 用户 ID 与话术哈希持久化（数据安全评估）

- **原文位置**：§4「AI 回复安全与去重」明确要求保留用户 ID 与话术哈希。
- **建议**：审计最少保留期、是否可使用受控标识/加密存储、日志是否泄露原始 ID、冷却到期清理及跨账号隔离。若存储结构要改，应另行批准迁移策略；本轮不改原文。

## 6. 固定调度/输入参数与既有算法可能冲突（先核对）

- **原文位置**：§2 退避节奏 500ms→1s→2s→5s→10s/最长 30s；§4 输入 2～3 个用户感知字符、500～900ms；§3.3/3.4 的安全区域与随机坐标参考值。
- **建议**：变更前审核现有参数是否已经由配置或用户授权决定；规范的“参考”数值与硬约束要区分。对于正式业务逻辑，不用“为了符合文档”作为绕过现有行为保护要求的理由。

## 7. 手册表达是目标约束，不是实现验收结论（应持续核验）

- **原文位置**：§1–§4 多处“须”“严禁”。
- **建议**：建立代码落点、职责归属、可测试断言和未实现项映射；不以导航文件出现某个规则即宣布代码已经满足。

**处理原则**：第 1–3 项及 PP 第 0 节架构强制约束和相关职责修订已获授权；第 4–7 项仍仅是建议，不构成修改授权。
